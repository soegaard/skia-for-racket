# PDF stage: validation and application

## Baseline and verification boundary

Apply this stage to `soegaard/skia-for-racket` at
`ccabb4741edc227a1dbeba91a47adf5082d7417f` ("Add advanced codec support").
It builds on the user's green 0.20 run: 219 source cases, 240 Skia and 27
HarfBuzz required symbols, doctor, and the GIF/WebP/orientation visual probe.
The existing ICC and codec implementations are preserved.

**No Racket compilation or native Skia execution was possible in the authoring
environment. No PDF generated by this new Racket implementation has been
rendered or visually approved here.** Do not interpret source checks as a
successful host run.

Authoring validation consists of delimiter/string and test-suite checks on the
new source, public API/native-signature review, patch-context checks against
fetched source excerpts, and compilation/execution of the C ABI mirror. The
mirror checks copied C layouts, not the actual native binary. The optional
Python PDF inspector is a development tool, not a library runtime dependency.

On a 64-bit host the PDF C mirror reports:

```text
PDF ABI mirror passed: metadata=80 timestamp=10 pointer=8
```

Expected after applying: **252 source test cases**, comprising 76 pure,
6 lifetime, and 170 native cases. Runner groups are:

```text
54 existing pure
 6 lifetime
10 codec pure
12 PDF pure
132 existing native
17 codec native
21 PDF native
```

Required native symbols become **247 Skia** and **27 HarfBuzz**. Seven Skia
symbols are added: metadata-backed PDF construction, begin/end page, close,
abort, unref, and copied SkString construction. No new native binaries or fonts
are included.

## Apply and run

From the repository root, with the patch in the local `downloads` directory:

```bash
PATCH="downloads/skia-for-racket-0.21.0-pdf-output-20260925.patch"
RACKET="/Applications/Racket v9.3.0.2/bin/racket"
RACO="/Applications/Racket v9.3.0.2/bin/raco"

git apply --check --verbose "$PATCH" &&
git apply "$PATCH" &&
git diff --check &&

python3 tools/static-check.py &&

cc -std=c11 -Wall -Wextra -pedantic \
  tools/check-codec-abi.c -o /tmp/skia-codec-abi-check &&
/tmp/skia-codec-abi-check &&
cc -std=c11 -Wall -Wextra -pedantic \
  tools/check-pdf-abi.c -o /tmp/skia-pdf-abi-check &&
/tmp/skia-pdf-abi-check &&

bash tools/audit-symbols.sh &&
bash tools/audit-harfbuzz-symbols.sh &&

"$RACO" make \
  main.rkt \
  bitmap.rkt \
  tools/doctor.rkt \
  run-tests.rkt \
  tests/pdf-pure-test.rkt \
  tests/pdf-native-test.rkt \
  examples/pdf-documents.rkt &&

"$RACKET" tools/doctor.rkt &&
"$RACKET" run-tests.rkt &&

mkdir -p output &&
"$RACKET" examples/pdf-documents.rkt output/pdf-documents-0.21.pdf &&
python3 tools/update-source-sums.py
```

`SOURCE-SHA256SUMS.txt` is deliberately not modified by the patch; regenerate
it in the complete patched checkout as above. Nothing is pushed to GitHub by
this delivery.

To run without loading native libraries:

```bash
"$RACKET" run-tests.rkt --pure
```

This requests 82 pure/lifetime cases, not the 170 native cases.

## Inspect the actual PDF

The example writes `output/pdf-documents-0.21.pdf`, with three pages:

| Page | Size in points | What to inspect |
|---|---|---|
| 1 | 612 × 792 | Vector geometry, native gradient, clipped/transformed drawing, ordinary text. |
| 2 | 792 × 612 | Simple/shaped text, paragraph layout, an embedded image, repeated recorded pictures. |
| 3 | 480 × 480 | Image-filter shadow/blur and dashed paths; compare backend fallback behavior. |

The files `pdf-documents-0.21.page-1.png` through `.page-3.png` are **raster
reference drawings**, not PDF rasterizations. They deliberately use the same
three drawing procedures on raster surfaces. Open the PDF in Preview or another
PDF renderer and compare it with those references. Check every page for clipping,
missing content, changed placement, expired-page contamination, and effect
fidelity. Zoom into the first page's geometry and text.

With the optional `pypdf` Python package installed:

```bash
python3 tools/inspect-pdf-output.py --probe output/pdf-documents-0.21.pdf
```

This parses the page tree, media boxes, content streams, font resources,
embedded image resources, and metadata. It asserts the example's page sizes,
checks that the first page contains path and text operators rather than a
flattened image, and checks that the second page embeds its explicit image.
It reports font embedding and extraction samples without assuming every font
or shaped run provides ideal Unicode reading order. It does not render pages
or certify PDF/A.

Poppler is another optional independent development check:

```bash
pdfinfo output/pdf-documents-0.21.pdf
pdffonts output/pdf-documents-0.21.pdf
pdftotext -layout output/pdf-documents-0.21.pdf output/pdf-documents-0.21.txt
pdftoppm -scale-to 1200 -png output/pdf-documents-0.21.pdf output/pdf-rendered
```

Inspect all three `pdf-rendered-*.png` files. Differences in antialiasing are
not necessarily defects; missing geometry, incorrect positions, page-size
errors, or unwanted whole-page rasterization are.

## Regression coverage

The added tests cover metadata ABI and validation; fractional point dimensions;
explicit/optional dates and UTF-8; output byte limits; multiple pages; stale
canvas rejection, including after a later page begins; abort/finish/close rules;
independent byte copies; wrong-thread rejection; scoped multiple return values;
raised non-exception values and continuation escapes; expired-scope reentry;
protected canvas stacks; native drawing dependency retention; safe publication;
and destination preservation when drawing fails.

RackUnit's PDF checks are framing/page-tree smoke checks, not a general PDF
parser or native heap leak detector. Native page rendering, font embedding,
text extraction, and effect fidelity require the independent checks above.
There is no new platform-portability or PDF/A conformance claim.

The historical full Unicode baseline is 10274 line-break and 91707 bidi-character
cases. It is not rerun by the main command above. To revalidate it:

```bash
RACKET="$RACKET" bash tools/run-unicode-conformance.sh
```
